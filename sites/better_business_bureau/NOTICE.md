The instance_seed/better_business_bureau.db SQLite database is not captured
content: the image build regenerates it from the tracked source_catalog.json
and seed_data.py (PYTHONHASHSEED=0 + canonicalize_seed.py, see .build-
generated-seed and the Dockerfile build step). Because the canonical rebuild
serializes through the builder's SQLite/SQLAlchemy versions, the seed's
byte digest is build-image-specific: with this repo's pinned runtime image
(python:3.12-slim-bookworm + requirements.lock, SQLAlchemy 2.0.36) independent
builds are byte-identical (SHA256 125f165d7fdc203482d0a9f3068eacb9200fe9594b7e61c4e7b0e250f3d6e24e);
a build outside that image (e.g. the contributor's local venv) produced
SHA256 eb3c098e96e3b1a51a9eb62638576957c222899939622f2eb9e23e6b47e5d48b for
the same source data. Ground truth in verify/grade.py is content-anchored
(row ids, counts, dates), so it holds for both digests.
